## 四态机（本阶段的核心）

优先级 **CONFIG > LIVE > CLOCK > WAITING**，每包独立计时：

| 状态 | 触发条件 | 灯阵显示 |
|---|---|---|
| **CONFIG** | 没有 WiFi 配置 / 连不上 / 长按 5 s 强制进入 | 琥珀色 **"SETUP"** 呼吸（10 fps） |
| **LIVE** | 5 s 内收到过 type=2 像素包 | 上位机画面，来一帧推一帧 |
| **CLOCK** | 像素包超时 **且** NTP 已同步 | **HH:MM:SS 彩虹时钟** + 底行秒进度 |
| **WAITING** | 像素包超时 **且** 时间还没同步 | "WAITING" 横向滚动（琥珀色） |

> WAITING 这层是必须的：**时钟恰恰是在上位机失联时才显示的**，冷启动且 NTP 未同步时总得显示点东西，不能是空白或错的时钟。
>
> CONFIG 是配网态，整个 `loop()` 走另一条路：不开 UDP、不注册 mDNS、不同步 NTP，
> 只跑门户 + 表头演示 + 灯阵呼吸提示。详见 [docs/08](../docs/08-wifi-provisioning.md)。

时钟自身的渲染帧率是 **30 fps**（够用即可），与灯阵那条链路无关。

## 首次使用：手机配网（不用改代码）

WiFi 的 SSID 和密码**不写死在代码里**，烧完固件用手机配一次就行：

```
1. 上电。灯阵开始呼吸琥珀色的 "SETUP" → 说明进了配网模式
2. 手机连热点 dash-XXXXXX（默认无密码）
3. 浏览器打开 http://192.168.4.1 —— 多数手机会自动弹出，不用手动输
4. 页面里点选你的 WiFi（2.4 GHz），填密码，点「保存并连接」
5. 设备重启，热点消失。灯阵开始显示彩虹时钟 → 成功
```

完整说明见 [docs/08](../docs/08-wifi-provisioning.md)。

三种会进配网模式的情况：

| 情况 | 说明 |
|---|---|
| 从没配过 | EEPROM 空，`secrets.h` 也没填 → 上电直接开热点 |
| 配过但连不上 | 15 s 连不上（密码错 / 换路由器 / 5 GHz）→ 自动重开热点 |
| **长按 FLASH 键 5 秒** | 手动强制进入，用来改 WiFi 而不必重新烧录 |

> ⚠️ **ESP8266 只支持 2.4 GHz。** 双频合一的路由器请确认广播了 2.4G。

### 还想用写死的老办法

`include/secrets.h`（已在 `.gitignore` 中）填了就仍然生效 —— 它只是**兜底**：

```cpp
#define WIFI_SSID       "YOUR_2.4G_SSID"
#define WIFI_PASSWORD   "YOUR_PASSWORD"
```

**EEPROM 优先级更高**：手机配过一次之后，`secrets.h` 就再也不起作用了。
填了它只是省掉"第一次要拿手机配一下"这一步，换 WiFi 仍然要重新烧录。

**现在不需要填 IP 了** —— 固件默认 DHCP，并注册 mDNS 服务让上位机自动发现。

设备上电后会打印自己的主机名，形如 `dash-A1B2C3`：

```
[WiFi] 已连接  IP=192.168.5.37  RSSI=-48 dBm
[WiFi] 主机名 dash-A1B2C3
[mDNS] 已注册 dash-A1B2C3.local -> _dashboard._udp  port=8551
```

验证（**不用开上位机**）：

```bash
dns-sd -B _dashboard._udp              # 应看到 dash-A1B2C3
ping dash-A1B2C3.local
```

查不到通常是这三件事：**AP 开了客户端隔离**、跨了 VLAN、或 `config.h` 里 `kMdnsEnable` 为 `0`。
实在不通就用静态 IP 退回手动寻址，两种方式都保留着：

- **配网页面**里展开「高级：使用静态 IP」，填模块 IP 与网关（模块 `192.168.5.50`，网关 `192.168.5.1`）—— 不用重新烧录
- 或把 `secrets.h` 的 `USE_STATIC_IP` 改回 `1`

主机名取自 ChipId，多机同网**不会撞名**。

> ⚠️ **ESP8266 只支持 2.4 GHz。** 双频合一的路由器请确认广播了 2.4G。

## ⚠️ 烧录前先看这里

### GPIO3 和数据线是同一个脚

NeoPixelBus 的 I2S DMA 固定占用 **GPIO3**，而 GPIO3 同时是 **UART0 的 RX** —— 烧录时芯片全靠这一脚接收 esptool 的命令。

### 实测结论：不用拔灯阵，也不用按 RST

**2026-09-26 实测**：灯阵照接 VIN、灯正常点亮、不按 RST、460800 波特率直接
`pio run -t upload` —— **6.2 秒一次成功**（365792 字节，有效 470 kbit/s）。

也就是说灯阵负载根本不影响下载。以前「每次必须拔灯阵」属于误判。

### 真正的坑：串口被监视器占用

烧录失败的头号原因是**第三方串口监视器独占端口**，典型报错：

```
SerialException: device reports readiness to read but returned no data
(device disconnected or multiple access on port?)
```

注意它长得像硬件故障（掉线 / 供电不足 / 线材不行），但其实是端口争夺。
**Tabby、VSCode Serial Monitor、screen、minicom 都会独占** `/dev/tty.*`，
而 PlatformIO 管不着它们；自家 `pio device monitor` 在 upload 时会让位。

### 烧录失败怎么排

| 步骤 | 操作 |
|---|---|
| **1** | **关掉串口监视器**，然后 `lsof /dev/tty.usbserial-xxxx` —— 有输出就说明还被占着，先关干净再说。**这一步能解决绝大多数情况** |
| 2 | 想边看日志边烧，改用 `pio device monitor`（pio 自家会在 upload 时让位） |
| 3 | 仍失败才**断开灯阵 5 V**，只留 USB 给开发板 —— 老办法，仍可作兜底 |
| 4 | 再失败则**拔掉 GPIO3 → DIN 那根线**，排除 WS2812B 未上电时 ESD 二极管把 RX 拉死 |
| 5 | 波特率降到 115200（`platformio.ini` 的 `upload_speed`）。460800 下 GPIO3 还挂着 256 颗灯的 DIN，裕量偏薄；代价是烧录从约 8 s 变成约 30 s |
| 6 | 自动下载电路没工作时手动进下载模式：**按住 FLASH 不放 → 按一下 RST → 松开 RST → 再松开 FLASH**，立刻执行烧录 |
| 7 | 换一根确认能传数据的 USB 线（很多充电线不通信） |

第 6 步若是常态，在 `platformio.ini` 加 `upload_flags = --before=no_reset`。

> 反过来也说明一件事：**「延迟 I2S 初始化」对烧录毫无帮助**。下载阶段跑的是
> ROM bootloader，固件一行都不执行 —— `strip.Begin()` 写在 `setup()` 里任何一行都不影响它。
> `config.h` 的 `kBootBlackoutMs`（开机黑屏窗口）因此默认设 **0**。
> 只有当供电方式变化、开着上位机推全亮画面（约 1 A）烧录失败时，才把它改回 3000 并按 RST 抢窗口。

> **串口只能输出、不能收命令**（RX 被 DMA 占用）。`Serial.println()` 走 TX = GPIO1，完全正常。

## 接线

### 灯阵

| NodeMCU | 接 |
|---|---|
| D9 / RX (GPIO3) | → 第一块 8×8 的 DIN（3.3 V 直驱，无电平转换；**建议串 330 Ω，实际未串**） |
| microUSB | → **5 V / 2 A 适配器（整机唯一电源入口）** |
| VU（或 VIN） | → 灯阵 VCC，走粗线 |
| GND | → 灯阵 GND，回流线同样要粗 |

**整机只有一个电源**：5 V / 2 A 适配器插 microUSB 口，灯阵从 VU（或 VIN）取电。
容量充足（2 A 带约 1.1 A），**瓶颈在路径** —— 1 A 要过 microUSB 座子 + PCB 铜箔 + 排针。

> ⚠️ **必须实测全亮时的灯阵端 VDD**（量灯阵 VCC 对 GND，带载，不是空载）：
> **≥ 4.75 V** 放心用；4.50~4.75 V 勉强；**< 4.50 V** 必须改接法（ESP 会欠压复位）。
> 改法首选把灯阵换到 **VU**（VBUS 直接引出、路径最短），其次换粗而短的 USB 线。
>
> ⚠️ 本机 **VIN / VU / micro-USB VBUS 直连、无防反二极管**（实测）→
> **不要同时接第二个 5 V 电源**，会互相倒灌。烧录时换插电脑即可（此时灯阵不亮，仅 ~100 mA）。
>
> 详见 [docs/01 §1.5–1.6](../docs/01-hardware.md)。

### 表头

| 通道 | NodeMCU | GPIO | 接法 |
|---|---|---|---|
| ch1 | D1 | 5 | GPIO → **20 kΩ（±1%）** → 表头(+) ；表头(−) → GND |
| ch2 | D2 | 4 | 同上 |
| ch3 | D5 | 14 | 同上 |
| ch4 | D6 | 12 | 同上 |
| ch5 | D7 | 13 | 同上 |

电参数（2026-09-18 实测）：内阻 1.2 kΩ，满偏 **155.6 µA**。100% 占空比时 `3.3 V / 21.2 kΩ = 155.7 µA`，正好一格不多一格不少。

五个引脚都是 NodeMCU 上仅剩的、**支持 PWM 且不受启动电平约束**的脚。

> ⛔ **不要用 GPIO16 (D0)**：它是 RTC GPIO，`analogWrite()` 对它完全不生效。
> ⛔ **不要用 GPIO0/2/15**：strapping 引脚，上电瞬间会吐杂散脉冲。
> ⛔ **20 kΩ 绝对不能省**：直接接的话 3.3 V 灌进 1.2 kΩ = 2.75 mA = **17.7 倍过载**，线圈瞬间烧毁且不可逆。
>
> ⚠️ 早期文档写的是 200 kΩ / 20 µA，那组数差了 7.8 倍，已作废。**如果你手上还焊着 200 kΩ，指针只会动一点点。**

## 按键操作（串口收不了命令，交互只能靠它）

板载 **FLASH 键**（GPIO0 / D3）：

| 操作 | 效果 |
|---|---|
| **短按**（< 0.7 s） | 切换底行秒进度样式：进度条 → 关闭 → 刻度 |
| **长按**（≥ 0.7 s） | 切换时钟明度：32 → 40 → 48 → 64 循环 |
| **超长按**（≥ 5 s） | **进入配网模式**（开热点 `dash-XXXXXX`），灯阵呼吸 SETUP。换 WiFi 时用 |

三种样式都可以现场看，选定后把 `config.h` 的 `kDefaultSecRowVariant` 改掉就不用每次按了。

### 时钟版面：HH:MM:SS

32 列要放 6 位数字 + 2 个冒号，**5×7 字模需要 37 列放不下**，所以用 4×7 窄体字模：

```
   x:  0 │ 1-4 │5│ 6-9 │10│11│ 12-15 │16│ 17-20 │21│22│ 23-26 │27│ 28-31
         │ H1  │ │ H2  │ :│  │  M1   │  │  M2   │ :│  │  S1   │  │  S2
  y=0..6 │         HH : MM : SS        │
  y=7    │ 底行秒进度 32 px            │
```

- 数字起点 `kDigitX = {1, 6, 12, 17, 23, 28}`，冒号在 x = 10 / 21（白点，y=2 与 y=4）
- 秒已经用数字显示了，所以**冒号常亮**不闪 —— 闪烁反而像时钟在重启
- 每位平均点亮 12.6 颗，6 位最坏 84 颗（`00:00:00` 这种全是 0/8 的组合）

### 底行（y=7）放什么

时钟占满 32 列后，原来的右侧 8×8 装饰区没有位置了，秒的"动感"由底行承担：

| 样式 | 点亮 | 特点 |
|---|---|---|
| **秒进度条**（默认） | 32 颗，走过部分由暗到亮 | 一眼看出 60 秒走了多少，最直观 |
| 关闭 | 0 | 最省电，画面最素 |
| 刻度 | 32 颗，多为 6%/22% 暗点 | 每 5 秒一个刻度，当前区间加亮 |

### 时钟的电流估算（用 `tools/clock_preview.py --scan` 复算）

各明度 V 下**最坏时间组合**（`00:00:58` —— 数字最密且秒进度条几乎全满）：

| V | 秒进度条 | 关闭 | 刻度 |
|---|---|---|---|
| 32 | 397 mA | 331 | 364 |
| 40 | 496 mA | 414 | 454 |
| **48（默认）** | **595 mA** | 497 | 545 |
| 64 | 794 mA | 662 | 727 |
| 72 | 893 mA ⚠ | 745 | 818 |

> 超过 Σ=12755（≈1000 mA）时固件的软件封顶会介入整体缩放，
> 结果是画面变暗且**各通道比例失真**（彩虹颜色会偏）。所以别迷信封顶。
> 参考工程实测的观感档位是 V=50，默认 48 与它接近。

## NTP

上电连上 WiFi 后自动 `configTzTime("CST-8", ...)`。串口会打印同步结果；同步成功那一行是这样的：

```
[Clock] 已同步  本地时间 21:47:35
```

时间有效性判据是 `time() > 1700000000`（≈2023-11）。NTP 没通时 `time()` 返回 1970 附近的小值，会被判成无效 → 走 WAITING。

### 2 小时重同步

`sntp_set_update_delay()` **在本 core 里不存在**（framework-arduinoespressif8266 3.1.2 / lwip2 的两个 `sntp.h` 都没有这个声明，编译已验证）。所以固件自带一个 2 小时定时器，到点重调一次 `configTzTime()` 强制刷新。这条路不依赖任何 lwIP 内部符号。

### NTP 常见问题

| 现象 | 原因与处理 |
|---|---|
| 一直停在 WAITING | WiFi 通但 UDP 123 出不去。常见是路由器开了 AP 隔离，或园区网封 NTP。换个 NTP 服务器试试 |
| 时间差整整 8 小时 | 时区串写错了。`"CST-8"` 是东八区，别写成 `"CST+8"`（POSIX 符号与直觉相反） |
| 时间差 16 小时 | 把 `configTime(8*3600, ...)` 和 `localtime()` 混用了 → 二次偏移。固件已用 `configTzTime`，不会犯这个错 |

## 上电后会发生什么

| 顺序 | 阶段 | 现象 |
|---|---|---|
| 0 | **黑屏窗口**（`kBootBlackoutMs`，**默认 0 = 关闭**） | 默认跳过，直接进扫针自检。仅在「供电变弱 / 开着上位机推全亮画面时烧录失败」才改回 3000，届时灯阵全黑并串口提示「趁现在点 Upload 可直接烧录」 |
| 1 | **扫针自检** | 5 路表头同时 0% → 100% → 0%，约 2.2 s。确认 5 个 PWM 通道硬件上都通、指针没卡死 |
| 2 | **连 WiFi** | 用 EEPROM 里的配置；没有则回退 `secrets.h`；都没有 → 跳到 2b。串口打印 IP、主机名、RSSI |
| 2b | **配网模式**（没配置 / 15 s 连不上） | 开热点 `dash-XXXXXX`，灯阵呼吸琥珀色 SETUP，等手机来配。配完自动重启 |
| 3 | **注册 mDNS + 启动 NTP** | 只在联网成功时做，串口打印注册的 mDNS 服务与 NTP 服务器 |
| 4 | **WAITING → CLOCK** | NTP 同步成功后立刻转时钟；在此之前滚动显示 WAITING |
| 5 | **LIVE** | 上位机开始推像素包后接管画面，停/NTP 都不影响 |
| — | **三角波演示** | 表头：从未收到过 type=1 包，或已收过但超时 5 s —— 两种都跑同一套演示扫描 |

> 表头演示与超时是**两回事**：看过演示不代表看过演示就不能再看。
> 只要连续 5 s 没有 type=1 包，指针就会回到演示扫描（缓动过渡，不瞬跳）；
> 上位机恢复发包则立刻接管。这个判断和灯阵超时各自独立计。

## 表头调试成不成，看这个核对清单

```bash
cd <项目根目录>
# ⚠️ 下面这行必须先执行，$PY 才会有值；且所有路径都假定你在项目根目录。
# （换成 python3 也一样，三个工具都只用标准库）
PY=python3

$PY tools/meter_test.py --mode list                      # 列出全部模式
$PY tools/meter_test.py --mode hold  --value 50          # 5 路都停 50%
$PY tools/meter_test.py --mode per --values 10 30 50 70 90
$PY tools/meter_test.py --mode stairs                    # 每 10% 停 2 s
$PY tools/meter_test.py --mode sweep                     # 三角波
$PY tools/meter_test.py --mode step --step-values 0 100  # 阶跃
$PY tools/meter_test.py --mode walk                      # 随机游走
```

| 模式 | 验证什么 | 通过标准 |
|---|---|---|
| `hold 50` | 静态位置 | 指针稳稳压在行程中点，**无肉眼可见抖动** |
| `hold 100` | 满偏 | 指针走到**接近行程末端**并稳住。若明显到不了，见下节 |
| `per 10 30 50 70 90` | 通道独立 | 5 个指针高低依次递增，**没有互相串扰** |
| `stairs` | 机械线性 | 每 10% 的偏转间距肉眼等距；**没有某一档卡住不动** |
| `sweep` | 缓动平滑 | 全程匀速无顿挫、无抖动、无"打弓"振荡 |
| `step 0 100` | 阶跃响应 | 约 0.6 s（3τ）到位，**过冲极小** |
| `walk` | 10 Hz 跟随 | 指针运动自然，看不出 100 ms 的台阶感 |

### 常见现象与判断

| 现象 | 含义 | 处理 |
|---|---|---|
| **指针到不了头（约走到 91%）** | ✅ 大概率正常 | 那只电阻其实是 **22 kΩ** 标准值（141.4 µA = 91%）。用万用表 Ω 档确认，想满就换成 20 kΩ ±1% |
| 指针只动很小一点（约 10%） | ❌ 焊的是 200 kΩ | 换成 20 kΩ。旧文档的 163.8 kΩ / 200 kΩ 全部作废 |
| 某一路完全不动 | 该路 20 kΩ 虚焊 / 表头断线 / 反接 | 先查该路引脚的平均电压：50% 时应约 1.65 V |
| **只有前几路动、后面几路全无反应** | ✅ 固件几乎不可能错：5 路共用同一套初始化循环，错只会全错。**几乎必然是后几路的接线**（接到了相邻排针 / 用了 D0 或 TX 之类不支持 PWM 的脚） | 逐路核对 `config.h` 的 `kMeterPins` 与实际插入的丝印；用 `--mode per` 单路隔离 |
| 指针全程轻微抖动 | 1 kHz PWM 纹波叠加机械共振 | 把 `kPwmFreqHz` 改成 20000（分辨率不受影响） |
| 听到线圈啸叫 | 同上 | 同上 |
| 指针黏滞、回零拖沓 | 缓动太重 | `kMeterAlpha` 调到 0.08~0.10 |
| 看得见 100 ms 台阶感 | 缓动太轻 | `kMeterAlpha` 调到 0.03 |
| 上位机停了，指针停在原地不动 | 不是故障 | 等 5 s —— 超时后会进入演示扫针模式来回扫（缓动过渡，不瞬跳） |

### 想要更大摆幅

| 选项 | 满偏 | 做法 |
|---|---|---|
| **保持现状（推荐先试）** | ~91~100% | 什么都不改。表头**没有刻度**，90% 和 100% 肉眼几乎一样 |
| 换 20 kΩ ±1% | 100% | 若万用表量出实际是 22 kΩ，换掉即可，其它一律不用动 |

> 各表头之间有个体差异（±5% 很常见），统一校准靠 `config.h` 里的 `kMeterTrim[5]`。
> 注意 **trim 只能减小不能增大** —— duty 上限 1023 已经是 3.3 V 直流，物理到顶。

## 诊断输出

```
[Meter] LIVE    %:  50.0  50.0  50.0  50.0  50.0   duty:  512  512  512  512  512   pkt=1204  loss=0.0%
[CLOCK] fps=30.1  pkt=0  loss=0.0%  brt=128  clkV=48  mA=523  cap=0  secrow=进度条  rssi=-48  heap=29840
```

`[Meter]` 行每 500 ms 一次（`-` 为 DEMO / TIMEOUT 状态），状态行每秒一次。

| 字段 | 含义 | 该警惕的值 |
|---|---|---|
| 方括号里的状态 | `LIVE` / `CLOCK` / `WAIT` | 一直在 `WAIT` → NTP 没通 |
| `%` / `duty` | 5 路的当前显示百分比与占空比 | `duty` 与上位机发的不一致 → 查 `kMeterTrim` |
| `pkt` / `loss` | 像素包计数与丢包率 | `loss` > 2% → 查 WiFi 信号/信道干扰 |
| `fps` | 实测推帧率（CLOCK 时约 30） | LIVE 下明显低于发送率 → WiFi 或 CPU 瓶颈 |
| `brt` | LIVE 时生效的全局亮度（固件上限 128） | |
| `clkV` | 时钟明度，长按按键循环 | |
| `mA` | 本帧软件估算电流 | 长期接近 1000 → 电源吃紧 |
| `cap` | 本秒触发功耗封顶次数 | 频繁非 0 → 太亮了，降 `clkV` 或把底行关掉 |
| `rssi` | WiFi 信号强度 | < −75 dBm 该排查天线/位置 |
| `heap` | 剩余堆内存 | 持续下降 → 内存泄漏 |

> 板载 LED 每收到一个表头包会闪 30 ms。指针看不出变化时，
> 这盏灯能立刻区分「UDP 没到」还是「表头没反应」。

## 实现要点（改代码前先看）

- **`analogWriteRange(1023)` 不能删。** Arduino core 3.x 默认只有 **8 bit (255)**，与 2.x 的 1023 不同 —— 这是 breaking change。
- **`analogWriteRange/Freq` 必须在 `pinMode`/`analogWrite` 之前调用**，否则已有波形会被停掉。
- **缓动的 alpha 按实际 dt 缩放**（`alpha * dt / kMeterTickMs`）。主循环被 DMA / WiFi 拖慢时，时间常数 τ 保持不变，手感不会随负载漂移。
- **最近的 0.5 duty 内直接吸附**，否则 `display` 永远逼近不到目标，`duty` 会在末位反复抖动。
- **`writeMeter()` 只在占空比变化时才写硬件**，避免 100 Hz 无谓地重启波形。
- **latest-wins**：`pumpUdp()` 必须把 socket 读空。每 loop 只读一个包会让延迟线性增长 —— 那是"队列化"的隐形版本。
- **`CanShow()` 必须查**，否则 `Show()` 会阻塞等 DMA。
- **`pushFrame()` 不得修改 `gFrameXY`**。同一帧可能被重复推，就地乘亮度会让画面一次比一次暗，且极难排查。
- **`Serial.begin()` 必须早于 `strip.Begin()`**，否则灯全不亮。
- **`WiFi.setSleepMode(WIFI_NONE_SLEEP)` 不能删。** modem sleep 会在收包路径上插入 100~300 ms 尖峰。
- **配网时 `WiFi.mode()` 必须是 `WIFI_AP_STA`**，只设 `WIFI_AP` 的话 `scanNetworks()` 直接失败，页面下拉框会是空的。
- **EEPROM 写完必须 `commit()`，写完还要回读校验。** 少了前者重启即丢且不报错；少了后者 flash 写坏了也发现不了。
- **切回 DHCP 要显式 `WiFi.config(0,0,0,0,...)`。** 上一份配置是静态 IP 时 SDK 会一直沿用旧地址。
- **配网密码不做 trim。** 密码首尾的空格是合法字符，trim 掉会连不上且极难排查（SSID 才 trim）。
- **进配网的超长按判断必须写在 `if (pressed == gBtnPrevPressed) return;` 之前**，否则按住期间根本进不去分支。
