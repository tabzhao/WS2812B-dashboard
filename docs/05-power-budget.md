# 05 · 功耗预算与亮度上限

## 5.1 电流模型

WS2812B 内部每个颜色通道是一个恒流源，典型 **20 mA @ 满值(255)**。因此：

```
单颗电流    I(mA)  = 20 × (R + G + B) / 255 = 0.0784 × (R+G+B)
单颗满白    R=G=B=255 → 60 mA
整屏满白    256 × 60 mA = 15.36 A  ← 理论绝对上限（约 77 W）
```

第二行那个 15 A 数字要牢记：**这块屏在最坏情况下能吃掉 15 A**。你目前靠"内容稀疏 + 亮度压低"把它控制在 1 A 以内，一旦某个动画全屏全白，电流会瞬间翻十几倍。所以功耗必须当成设计约束，而不是"实测没事就算没事"。

## 5.2 关于你实测的 5 W

实测 **5 V / 1 A = 5 W**，说明当前展示的内容大约是**平均 3.9 mA/颗**（约占满白电流的 6.5%）。这是一个偏保守、而且跟具体画面强绑定的数字 —— **换一个更亮的动画就会突破**。

因此本项目的功耗预算定为：

| 场景 | 建议峰值 | 依据 |
|---|---|---|
| 仍用电脑 USB 演示 | ≤ 800 mA | 很多 USB 口限 500 mA，加上 NodeMCU 板载自恢复保险丝 |
| 外接 5 V/2 A 电源（**推荐**） | ≤ 1500 mA | 留一倍余量给电源老化和线损 |

**推荐直接上外接 5 V/2 A**，别长期吊在 USB 口上。

## 5.3 彩虹时钟的亮度–电流表

时钟改成 **HH:MM:SS** 后：6 位 4×7 窄体字模最坏点亮 **84 颗**（`00:00:00` 这类全是 0/8 的组合），加两个冒号 4 颗、底行秒进度 32 颗，权重合计约 **100 颗当量**（进度条多数像素在中低明度，不是满亮）。彩虹色是饱和色相，(R+G+B) 平均为 1.5×255，所以单颗电流 ≈ `0.1176 × V` mA（V 为**最终生效明度**，即已经乘过全局亮度之后的值）。

| 生效明度 V | 位 | 84 颗（仅字模） | 最坏组合含底行 | 评价 |
|---|---|---|---|---|
| 255 | 满 | 2.52 A ❌ | 3.00 A ❌ | 远超任何 USB 供电能力 |
| 128 | 50% | 1.27 A ❌ | 1.51 A ❌ | |
| 100 | 39% | 0.99 A ⚠️ | 1.18 A ❌ | |
| 80 | 31% | 0.79 A ✅ | 0.94 A ⚠️ | 电源有 1.5A 余量才行 |
| 64 | 25% | 0.63 A ✅ | **0.79 A ✅** | 固件最高档 |
| **48** | 19% | 0.47 A ✅ | **0.60 A ✅** | **固件默认档** |
| 40 | 16% | 0.40 A ✅ | 0.50 A ✅ | |

> **参考工程验证过的档位：`BRIGHTNESS = 50`。** 它就是你现在电脑上看到的那块屏的实际观感。**本项目默认 V = 48**（与它基本同档），最高档 64 也在安全范围；再往上会逼近 1000 mA 软件封顶。
>
> 精确值用 `tools/clock_preview.py --scan --v N` 复算，它扫的是全部 HH:MM:SS 组合里的最坏者。

### ⚠️ 降饱和度是无效操作

想省电时不要去降饱和度 —— 低饱和会趋近白色，(R+G+B) 从 1.5×255 涨到 3×255，**电流反而翻倍**。

**唯一有效的降功耗手段是降明度 V。** 想要"淡一点"就调 V，不要调 S。

## 5.4 软件功耗封顶（必须实现）

不管怎么设计都有可能出现"某个动画忘了限亮度"的情况，所以固件里要做**逐帧强制封顶**：

```cpp
constexpr uint32_t kMaxCurrentMa     = 1000;                  // USB: 800
                                                              // 外接2A: 1500
constexpr uint32_t kMaxChannelSum    = kMaxCurrentMa * 255 / 20;   // = 12755 @1000mA

void applyBrightnessAndPowerCap(uint8_t* rgb, uint8_t brightness, size_t n) {
    uint32_t total = 0;
    for (size_t i = 0; i < n; ++i) {           // n = 3 * pixelCount
        uint16_t v = rgb[i] * brightness / 255;
        rgb[i] = (uint8_t)v;
        total += v;
    }
    if (total > kMaxChannelSum) {
        uint16_t scale = (uint16_t)((uint32_t)kMaxChannelSum * 256 / total);
        for (size_t i = 0; i < n; ++i) {
            rgb[i] = (uint8_t)((uint16_t)rgb[i] * scale >> 8);
        }
    }
}
```

- 阈值换算：**`12755` 对应 1000 mA**；`10204` 对应 800 mA；`19132` 对应 1500 mA。
- 这个算法是**逐帧的**，全扫描一次 768 字节，在 ESP8266 上耗时几十 µs，可以忽略。
- 实测值通常比按 20 mA/通道算出来的低（真实灯珠多在 40~50 mA/颗满白），所以这些都是**保守估计**，留了余量。

## 5.5 电压跌落与颜色漂移

WS2812B 内部三颗 LED 的正向压降不同：**蓝 > 绿 > 红**。所以当你电源线径太细、线太长、滤波不足导致 **5 V 塌到 4.3 V 以下**时，最先出问题的是**蓝色** —— 表现为白色发黄、彩虹色系整体偏暖。

如果你看到"整屏偏黄"，第一件事**不是调代码，而是拿万用表量 LED 侧的 5 V**（而不是电源输出端）。

这也是 [01-hardware.md](01-hardware.md) 里要求 **1000 µF 电解 + 每块 0.1 µF 瓷片 + 足够粗的电源线**的原因。

## 5.6 检查清单

- [ ] 确定供电方式，并据此选定 `kMaxCurrentMa`（800 / 1000 / 1500）
- [ ] 时钟明度起步设 V ≈ 60~80
- [ ] 全屏动画内容重新核算（即便 V=80，256 颗也要 2.4 A）
- [ ] 长期运行后触摸电源线是否发热 —— 发热说明线径不足
- [ ] LED 侧实测电压 ≥ 4.8 V（空载）/ ≥ 4.5 V（满载）
