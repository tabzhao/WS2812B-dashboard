# 02 · 动圈表头驱动方案

> **2026-09-18 实测更正：** 早期记录的「20 µA 满偏」是错的，**差了 7.8 倍**。
> 据此算出的 163.8 kΩ / 200 kΩ 系列方案**全部作废**。本文已按实测值重写。

## 2.1 先看清这个器件的本质

| 参数 | 值 | 来源 |
|---|---|---|
| 内阻 Rm | 1.2 kΩ | 用户万用表实测 |
| **满偏电流 Ifs** | **155.6 µA** | 实测推算，见 2.0 |
| **满偏电压** | 1.2 kΩ × 155.6 µA = **186.7 mV** | 推算 |

它本质上是一个**电流计**：指针角度 ∝ 流过线圈的电流，与端电压几乎无关（端电压只是电流的副产物）。所以唯一要解决的问题是：**如何把一个 3.3 V 的 PWM 波，线性地转换成 0–155.6 µA 的电流**。

## 2.0 实测数据是怎么测出来的

用户用可调电源做的标定，这是本文全部数字的来源：

```
可调电源 3.3 V ── 串联电阻 20 kΩ ── 表头(+) ── 表头(−) ── GND
                                     Rm = 1.2 kΩ
回路串万用表电流档，读数 0.14 mA，指针走到 90%
```

反推：

```
Ifs = 0.14 mA / 0.90        = 0.1556 mA = 155.6 µA     ← 真实满偏电流
验算 R_total = 3.3 V / 0.1556 mA = 21 208 Ω
     R_series = 21 208 − 1 200  = 20 008 Ω ≈ 20 kΩ      ← 与所用电阻完全吻合 ✅
```

**两个验算独立完成却指向同一个数，说明这组参数可信。**

> **关于那 10% 的差额：** 按 20 kΩ 理论值算，电流应该是 155.7 µA（即 100%），但实测读到 140 µA。
> 两种解释都能说得通，且都不影响结论：
> - 万用表电流档的内阻分掉了约 2.4 kΩ（µA/mA 档的 burden voltage 很常见）
> - 或者实际焊的是 **22 kΩ** 标准值色环被读成了 20 kΩ（22k+1.2k=23.2 kΩ → 142.2 µA，与 0.14 mA 分毫不差）
>
> 核实办法：万用表电阻档量一下那只电阻。**是 22 kΩ 就换成 20 kΩ**（±1% 金属膜），即可得到正好 100% 行程。

## 2.2 三个备选方案比较

| 方案 | 做法 | 评价 |
|---|---|---|
| A. 恒压 + 电阻限流 | GPIO → 20 kΩ → 表头 | ✅ **选用**。零件最少、天然自保护、线性度够 |
| B. 恒压 + Howland 电流源 / 专用 IC | 运放搭 0–156 µA 恒流源 | ❌ 5 路要 5 套运放，成本高、零点漂移烦，收益不明显 |
| C. DAC（如 MCP4728）+ 电阻 | 4 路 12 bit DAC | ⚠️ 路数不够（要 5 路得两片），且 5 V 供电时电阻值要改；没必要 |

选 A 的关键理由是：**限流电阻同时是保护电阻**，见 2.5。

---

> ## ✅ 实际已建成的接法（以此为准）
>
> 每路：**GPIO → 串联电阻 ~20 kΩ / 1/4 W → 表头(+)，表头(−) → GND**
> 无 RC 滤波、无电位器、无电平转换。
>
> **结论：这是对的，而且自带保护，不用改。** 100% 占空比时电流 ≈ 155.7 µA ≈ 正好满偏。
> 唯一需要确认的是那只电阻究竟是 20 kΩ 还是 22 kΩ —— 见 2.0 的核实办法。

## 2.3 参数计算

```
目标：GPIO 输出 3.3 V（100% 占空比）时，电流恰好 155.6 µA

总需求电阻   R_total = 3.3 V / 155.6 µA = 21 208 Ω
表头自身贡献 Rm      =  1 200 Ω
串联外接     R_s     = 21 208 − 1 200 = 20 008 Ω  → 取 20 kΩ
```

**器件选型：20 kΩ ±1% 金属膜，1/4 W**（温度系数 ≤ 100 ppm/°C）

若想逐只精确补偿表头差异，可用 **18 kΩ 固定 + 5 kΩ 多圈电位器**（可调 18~23 k，覆盖 ±10%）。

> **关于内阻精度：几乎不用管。** 表头内阻 1.2 kΩ 即使差 ±20%（240 Ω），相对 20 kΩ 也只有 1.1% 的误差，肉眼分辨不出，且能靠软件 `kMeterTrim` 吸收。

**⚠️ 换算表（别再套用旧数字）**

| 若满偏电流真是… | 需要的 R_total | 需要的 R_series |
|---|---|---|
| ~~20 µA（旧数据，已废）~~ | ~~165 kΩ~~ | ~~163.8 kΩ~~ |
| **155.6 µA（实测）** | **21.2 kΩ** | **20 kΩ** |

## 2.4 关于 RC 滤波：不必加

当前接法**没有滤波电容，也不需要加**。理由：

- 限流电阻在**前面**，线圈看到的是 0 / 155.7 µA 的方波**电流**，不是电压方波直灌；线圈自身电感先把电流平滑了一大半。
- 表头机械带宽只有 2~5 Hz，**1 kHz 纹波它根本跟不上**，指针只响应平均值。
- 平均值 = 占空比 × 155.7 µA，线性度没问题。
- 附带好处：轻微高频颤动能**降低静摩擦**，指针在小信号附近反而不容易卡住。

> ⚠️ **如果将来改成"低阻限流 + RC 滤波"的接法**，电容必须在**大电阻之前**。若把电容放在限流电阻之后（或直接并在表头两端），会和它组成慢网络，叠加机械惯性后指针会明显黏滞回零拖沓。
> 当前 20 kΩ 直连接法下这条警告不适用 —— 压根没有电容。

## 2.5 为什么烧不掉（自保护特性）

这是本方案最大的优点：

```
GPIO 无论输出什么 —— 高电平、PWM 100%、上电误触发、代码跑飞写满 ——
这条支路的电流上限恒为：3.3 V / 21.2 kΩ = 155.7 µA ≈ 正好 1× Ifs
```

也就是说，**该电阻既是限流器也是保险丝**。最坏情况是指针走到满偏，正是设计工作点，不会损伤游丝。

反过来说，唯一的致命错误是：**忘了串那个 20 kΩ**。一旦 GPIO 直接接表头：

```
3.3 V / 1.2 kΩ = 2.75 mA = 17.7 倍过载  →  线圈瞬间烧毁且不可恢复
```

（旧文档按 20 µA 算写的是"137 倍"，那个数随 Ifs 更正而变小，但结论不变：**这个电阻一个都不能少**。）

顺带解释为什么避开 GPIO0/2/15：ESP8266 启动瞬间部分 strapping 脚会输出一段短暂的 PWM 脉冲。其余引脚即使有这问题，也被 155.7 µA 上限保护住了；但既然能避开，就避开。

## 2.6 功耗

| 项 | 计算 | 结果 |
|---|---|---|
| 单路总功耗 | 3.3 V × 155.7 µA | **0.514 mW** |
| 其中串联电阻 | (155.7 µA)² × 20 kΩ | 0.485 mW |
| 其中线圈 | (155.7 µA)² × 1.2 kΩ | 0.029 mW |
| **5 路全满偏** | | **2.57 mW** |
| 相对 1/4 W 电阻额定 | 0.485 / 250 | 约 **1/515** |

**对电源完全无压力**，系统性误差可以忽略。GPIO 单脚承担 156 µA，而 ESP8266 单脚上限是 12 mA —— **只用了 1.3%**。

## 2.7 PWM 配置要点

```cpp
analogWriteRange(1023);       // ★ 必须显式调用，见下方说明
analogWriteFreq(1000);        // 1 kHz；5 路共用一个全局频率
analogWrite(pin, value);      // value: 0..1023  →  0..155.7 µA
```

**已核对 Arduino core 3.1.2 源码**（`cores/esp8266/core_esp8266_wiring_pwm.cpp`）：

- **默认分辨率只有 8 bit**（`analogScale = 255`），不是 1023。core 3.x 起与 Arduino 上游对齐，与 2.x 的 1023 默认值不同 —— 这是一个 breaking change。要 10 bit 必须显式 `analogWriteRange(1023)`。
- **分辨率与频率基本无关**。`period = 80 MHz / freq`，只要 `period ≥ analogScale` 就能保持分辨率：1 kHz 时 period=80000，即便 60 kHz 也有 1333，仍 > 1024。所以"提高频率会损失分辨率"的说法在这里不成立。
- 频率被夹在 **100 Hz ~ 60 kHz**（超出会自动夹到边界）。
- 频率是**全局的**，5 路共享，无法分别设置。
- 实现方式不是专用 PWM 外设，而是 **Timer1 + 波形发生器（ISR）**。占空比很稳定，但要意识到它在吃少量中断时间；本项目用的是 DMA 推灯，不会关中断，因此不受影响。

调参建议：

| 现象 | 处理 |
|---|---|
| 无声、指针平滑 | 保持 1 kHz / 10 bit |
| 有可闻啸叫（线圈在 1 kHz 振动） | `analogWriteFreq(20000)`，仍保持 10 bit，且超出人耳范围 |
| 追求更细腻 | `analogWriteRange(4095)`（12 bit），1 kHz 下依然够用 |

## 2.8 校准流程

硬件侧全靠那只电阻，表头之间的个体差异用软件吸收。

**硬件标定（一次性）：**

1. 接好 GPIO → 20 kΩ → 表头，确认极性（反接会反向打表）。
2. 用 `tools/meter_test.py --mode hold --value 100` 让该路输出 100% 占空比。
3. 观察指针：应走到**接近但不超过**机械满偏。差得明显就把 20 kΩ 换成 18 kΩ 或 22 kΩ 看趋势。
4. 回零验证：发 `--value 0`，指针应回到机械零点。
5. 记下该路的实际满偏百分比，填进软件 `kMeterTrim`。

**软件微调：**

```cpp
// 每路的满偏修正系数，默认 1.00；标定后可微调 ±10%
static constexpr float kMeterTrim[5] = {1.00f, 1.00f, 1.00f, 1.00f, 1.00f};

// value16: 上位机发来的 uint16 (0..65535)
float norm    = (float)value16 / 65535.0f * kMeterTrim[ch];
uint16_t duty = (uint16_t)(norm * 1023.0f + 0.5f);
analogWrite(kMeterPin[ch], duty);
```

> `kMeterTrim` 只能**减小**行程，不能增大 —— duty 上限 1023 已经是 3.3 V 直流，物理到顶了。
> 想整体走得更满，必须减小串联电阻。

## 2.9 缓动（easing）

动圈表头机械响应时间典型 0.3~1 s，有效带宽只有 2~5 Hz。上位机以 **10 Hz** 发包（用户定），如果直接跳变，会看到明显的步进和指针"打弓"振荡。

建议**在固件侧做指数缓动**（这是渲染层的平滑，不是业务逻辑 —— 真表也是有惯性的）：

```cpp
// 目标值更新频率 = 10 Hz（协议侧），渲染循环频率 = 100 Hz
// alpha = 0.05 时时间常数 τ ≈ 20 次 × 10 ms = 200 ms
constexpr float kMeterAlpha = 0.05f;

displayed += (target - displayed) * kMeterAlpha;
```

| alpha | τ（渲染 100 Hz 时） | 手感 |
|---|---|---|
| 0.02 | 500 ms | 很沉稳，适合直径较大的表 |
| 0.05 | 200 ms | **推荐起点** |
| 0.10 | 100 ms | 偏灵敏，可能看到轻微过冲 |

**超时回落**用同一套缓动，只是 target 设为 0 —— 不要瞬间归零，让它慢慢落下来，和一个真实仪表断信号时一致。

### 固件侧的实现要点

```cpp
analogWriteRange(1023);        // ★ core 3.x 默认只有 255，必须显式设置
analogWriteFreq(1000);
pinMode(pin, OUTPUT);          // 必须在上面两行之后
analogWrite(pin, duty);        // duty: 0..1023 → 0..155.7 µA
```

- **接线：** GPIO → 20 kΩ → 表头(+)，表头(−) → GND。**不用 GPIO16(D0)**，它是 RTC GPIO，`analogWrite` 不生效。
- **缓动：** 100 Hz 渲染节拍，`displayed += (target - displayed) * alpha`。alpha 要按实际 `dt` 缩放，否则主循环被拖慢时手感会漂移。
- **吸附：** 差值小于 0.5 duty 时直接置为目标值，否则占空比末位会永远抖动。
- **超时：** 5 s 无包 → target 归 0，走同一套缓动慢慢落下来（不瞬跳）。
