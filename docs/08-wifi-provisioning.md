# 08 · WiFi 配网（Captive Portal）

> **目标：WiFi 的 SSID 与密码不再写死在代码里。**
> 新板子烧完固件直接上电 → 手机连它的热点 → 浏览器自动弹出配置页 →
> 填 SSID 和密码 → 保存 → 设备重启并联网。全程不用改代码、不用重新烧录。

| 关联 | |
|---|---|
| 服务发现（配完之后怎么被上位机找到） | [07-host-integration.md](07-host-integration.md) |
| 协议与超时 | [04-udp-protocol.md](04-udp-protocol.md) |
| 实现 | `firmware/include/netconfig.h`、`firmware/include/portal.h` 及同名 `.cpp` |

## 1. 为什么不用 WiFiManager

社区里做这件事的标配是 `tzapu/WiFiManager`。**本项目不用**，理由是它解决的是"别人的问题"：

| WiFiManager 会做 | 本项目为什么不要 |
|---|---|
| 自己管参数的存储 | 我们要把配置放 EEPROM 自己管，还要和 `secrets.h` 兜底逻辑混用 |
| 自己调 `WiFi.begin()` 并接管重连 | 本固件已有 `ensureWifi()` + mDNS 重注册顺序（[07 §0.1](07-host-integration.md)），两套重连逻辑会互相打架 |
| 附带一堆"信息页/更新页/自定义参数" | 我们要的只是「一个下拉框 + 一个密码框」 |
| 多一个第三方依赖 | 本项目在 mDNS 上吃过亏：多一个库，多一层不可控 |

用 core 自带的 `ESP8266WebServer` + `DNSServer` + `EEPROM` 自己写，总共约 300 行，**零第三方依赖**。

代价：Flash **+44 KB**、RAM **+2.2 KB**（见 §7）。4 MB flash 的板子完全无所谓。

## 2. 启动决策流程

```
                    ┌─────────────────┐
                    │     上电        │
                    └────────┬────────┘
                             ▼
                 ┌───────────────────────┐
                 │ EEPROM 里有没有配置？ │
                 └───┬───────────────┬───┘
                   有│               │没有
                     ▼               ▼
        ┌────────────────┐  ┌──────────────────────────┐
        │ 用它连 WiFi    │  │ secrets.h 真的填过吗？   │
        │ （15 s 超时）  │  │ （不是 YOUR_2.4G_SSID）  │
        └───┬────────┬───┘  └───┬──────────────────┬───┘
         成功│        │失败    填过│                │没填
             ▼        └────┐      ▼                │
   ┌──────────────────┐    │  用 secrets.h 连      │
   │ mDNS + NTP + UDP │    │  （15 s 超时）        │
   │ 正常运行         │    │      │                │
   └──────────────────┘    └──────┼────────────────┘
                                  ▼
                    ┌─────────────────────────────┐
                    │ 进入配网模式（ST_CONFIG）   │
                    │ 开热点 dash-XXXXXX          │
                    │ 灯阵呼吸显示 SETUP          │
                    └─────────────────────────────┘
```

三条判据要记牢：

1. **EEPROM 优先。** 手机配过一次之后，`secrets.h` 就再也不起作用了。
2. **`secrets.h` 是兜底，不是必须。** 它没有、或还是模板占位符 `YOUR_2.4G_SSID`，
   固件会直接跳过它去开热点 —— 不会傻等一个永远连不上的 SSID。
3. **连不上就进配网，不无限重试。** 15 秒（`kWifiConnectTimeoutMs`）还没连上就认为这份配置作废。

> `secrets.h` 这一层的存在意义只有一个：让「烧录时顺手填过一次」的老流程继续可用。
> 新用法请一律走配网页面 —— 换路由器、改密码都不用再动代码。

## 3. 三种触发配网的方式

| 方式 | 什么时候用 | 操作 |
|---|---|---|
| **自动**（最常见） | 没有配置，或有配置但连不上 | 上电后自己就进了，不用管 |
| **长按 FLASH 键 5 秒** | 要换 WiFi、改密码，而旧 WiFi 还能连上 | 按住板载 FLASH 键（GPIO0/D3）不放，5 秒后灯阵开始呼吸 SETUP |
| **页面里点「清除配置」** | 想让它彻底忘掉旧 WiFi | 在配置页点该链接，设备清 EEPROM 后重启 |

> 长按 5 秒这个档位是刻意与「切亮度的 0.7 秒」拉开一个数量级的。
> 实现上有个坑：进配网的判断必须写在 `handleButton()` 里那个
> `if (pressed == gBtnPrevPressed) return;` **之前** —— 写在后面就永远触发不了，
> 因为按住期间状态没变化，压根进不到下面的分支。

配网热点**默认开放（无密码）**。想加密就把 `config.h` 的 `kPortalApPassword` 填成 8 位以上的字符串，
第一次连热点时要输它。

## 4. Captive Portal 是怎么做到"连上就弹页面"的

只起一个 WebServer **不叫** Captive Portal —— 那样手机连上热点后毫无提示，
用户得自己猜到要打开浏览器输 `192.168.4.1`。真正让它"自动弹"的是两件事：

| 机制 | 作用 |
|---|---|
| **DNSServer 通配**（`dns.start(53, "*", apIp)`） | 手机发出的所有域名查询，一律回答"就是我" |
| **404 → 302 到 `/`** | 无论手机访问哪个网址，都被重定向到配置页 |

手机/系统连上 WiFi 后会主动探测一个固定网址（iOS 探 `captive.apple.com`，Android 探
`connectivitycheck.gstatic.com`）。通配 DNS 把它们指到本机，本机再 302 到配置页 ——
系统一看"探测结果不是我预期的 204/Success"，就判定"这个网络需要登录"，于是自动弹出登录页。

> 少数 Android 机型不弹。兜底办法永远是同一个：连上热点后手动打开 `http://192.168.4.1`。
> 页面地址也打在串口日志里。

### 配网页面能做什么

| 元素 | 说明 |
|---|---|
| 附近网络下拉框 | 启动时自动扫描一次（1~3 s），按信号强度排序，**同名 SSID 已去重**（多 AP/中继会广播好几个同名项，不去重用户根本分不清选哪个）。点一下自动填进输入框 |
| WiFi 名称输入框 | 可以手动填 —— 隐藏 SSID 的网络扫不出来，只能手动输入 |
| 密码框 | 开放网络留空。**注意：密码不做 trim**，首尾空格是合法字符 |
| 高级：静态 IP | 默认折叠。只有确认网络不适合 DHCP 时才填，一般不用 |
| 重新扫描 / 清除配置 / 重启设备 | 底部三个链接 |

## 5. 配置存在哪儿

EEPROM 前 512 字节（ESP8266 的 EEPROM 是 flash 模拟的，见下）。

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | `magic` = `0x31434244` | 区分「没写过的 flash（全 0xFF）」和「真有配置」 |
| 4 | `version` = 1 | 以后改结构时用来拒绝旧配置 |
| 5 | `flags` | bit0 = 使用静态 IP |
| 6 | `ssid[33]` | 最长 32 字符 |
| 39 | `pass[65]` | 最长 64 字符 |
| 104 | `ip / gw / mask / dns` 各 4 字节 | 仅静态 IP 时有效 |
| 120 | `checksum` | 前面所有字节的异或（初值 0x5A） |

### 三个不做就会出事的点

**① `EEPROM.begin()` / `commit()` 一对都不能少。**
ESP8266 的 EEPROM 是把最后一个 flash sector 当 RAM 缓存：`begin()` 把 sector 读进缓存，
`put/get` 只改缓存，**`commit()` 才真正擦写 flash**。
忘掉 `commit()` 的现象是"重启后配置没了"，而且编译和运行时**都不报错**。

**② 写完必须回读校验。**
`commit()` 在电压跌落 / sector 损坏时未必返回 false。`netConfigSave()` 写完会重新 `load()`
一遍并逐字节比对，对不上就返回 false —— 立刻在页面上报错，而不是等下次上电才发现。

**③ 结构体的填充字节要先清零。**
`NetConfig` 里混着 `uint32_t` 和 `char[]`，编译器会插填充字节，内容是未定义的。
如果不清零就算 checksum，会出现"写进去的和读出来的不一致"。
`netConfigSave()` 里先 `memset(&c, 0, sizeof(c))` 再填字段，就是为此。

## 6. 完整流程（用户视角）

```
1. 给开发板上电（灯阵显示呼吸的琥珀色 SETUP → 说明进了配网模式）
2. 手机 WiFi 列表里找到 dash-XXXXXX，连上（默认无密码）
3. 系统自动弹出"需要登录"的页面；没弹就浏览器打开 http://192.168.4.1
4. 页面里点选你的 WiFi（2.4 GHz），填密码，点「保存并连接」
5. 设备保存配置并重启，热点消失
6. 十几秒内灯阵开始显示 HH:MM:SS 彩虹时钟 → 成功
   （若手机又能搜到 dash-XXXXXX → 没连上，重新进页面检查密码）
```

配完网后一切照旧：固件走 DHCP 拿 IP，注册 mDNS `_dashboard._udp`，
上位机自动发现 —— 这部分见 [07 §0.1](07-host-integration.md)。

> ⚠️ **ESP8266 只支持 2.4 GHz。** 双频合一的路由器请确认广播了 2.4G；
> 扫不到任何网络时页面顶部会给出这条提示。

### 防呆

配网热点开了 **10 分钟**（`kPortalTimeoutMs`）还没人配置，设备自动重启重试一次。
防的是"路由器临时断电 → 设备开一整天热点没人管"。

## 7. 开销（实测，`pio run` 输出）

| | 加配网前 | 加配网后 | 增量 |
|---|---|---|---|
| Flash | 317,695 B（30.4%） | 361,675 B（34.6%） | **+43,980 B** |
| RAM | 31,200 B（38.1%） | 33,424 B（40.8%） | **+2,224 B** |

大头是 `ESP8266WebServer` + `DNSServer` 这两个库。4 MB flash 的板子余量还很足。

## 8. 踩坑清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机连上热点但**不弹页面** | 部分 Android 机型不触发 Captive Portal 检测 | 手动打开 `http://192.168.4.1` |
| 页面下拉框**是空的** | `WiFi.mode()` 只设了 `WIFI_AP` | ★ 必须是 `WIFI_AP_STA` —— 纯 AP 模式下 `scanNetworks()` 直接失败 |
| 密码明明对，却连不上 | 密码被 trim 了 | 固件刻意不对密码做 trim；检查是不是填了多余空格 |
| 页面选了 DHCP，重启后**还是老 IP** | 上一份配置是静态 IP，SDK 一直沿用 | `connectWifi()` 里显式调 `WiFi.config(0,0,0,0,...)` 交回 DHCP |
| 长按 5 秒**没反应** | 超长按判断写在了 `if (pressed == gBtnPrevPressed) return;` 之后 | 必须写在那个 return **之前**，否则按住期间根本进不去 |
| 保存后重启，又回到配网页 | 密码错 / 是 5 GHz / 信号太差 | 重新配置。串口会打印连接过程 |
| 配网时灯阵**卡住不动** | 扫描阻塞了主循环 1~3 s | 已处理：扫描结果缓存，只有启动和点"重新扫描"时才扫 |
| 配网模式下串口一直刷 | 正常的 `[CFG]` 状态行 | 每 1 s 一行，含已连设备数，可用来确认手机连上了没 |

### 关闭配网（回到写死的老路）

把 `config.h` 的 `DASHBOARD_ENABLE_PORTAL` 改成 `0` 即可，代码会被整体剔除。
此时若没有可用配置，固件退化为"每 5 s 重试连接"，与加配网之前的行为一致。

> ★ 这个开关是**宏**而不是 `constexpr`：预处理器看不懂 C++ 变量，
> `#if` 里的 `constexpr` 会被当成未定义标识符求值为 0，整段代码被静默剔除且零警告。
> 这个坑在本项目踩过一次（代价是一次白烧）。改完开关后请用
> `strings firmware.elf` 复核二进制，比看"编译成功"可靠得多。
