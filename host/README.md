# 上位机（Rust + GPUI）

仪表盘的常驻上位机。用 GPUI（Zed 的 GPU 加速 UI 框架）做的桌面程序，
通过 UDP 把「字符串字模画面」和「5 路系统指标」推给 NodeMCU 终端。
协议见 [../docs/07-host-integration.md](../docs/07-host-integration.md)。

## 功能

- **自动发现设备**：无需知道 IP —— 用 mDNS 列出局域网里所有仪表盘，
  发现到第一台就**自动选中**（按名字排序，顺序稳定），可随时手动改选
- **灯阵与表头两路数据源独立设置**，互不绑定：
  - **灯阵**：`文字`（输入字符取 5×7 字模横向滚动）/ `频谱`（抓 Mac 正在播放的音乐做 FFT）/
    `无`（**完全不发像素帧**，设备端 5 s 后转彩虹时钟）
  - **表头**：`系统指标`（5 个下拉框各选一路）/ `音频频段`（5 路固定跟 低/中低/中/中高/高频）
  - 于是「灯阵走频谱 + 表头走系统指标」「灯阵关掉 + 只推表头」这类混搭都是允许的
  - 系统指标 6 选 1：整体 CPU 使用率 / 内存使用率 / 网络发送速率 / 网络接收速率 / 硬盘读取速率 / 硬盘写入速率
- **显式推送开关**：选中设备**只是定目标**，不发任何包；点底部「**开始推送**」才真正开始，
  按钮随即变「**停止推送**」。停止后设备 5 s 收不到包自动转演示扫针 / 彩虹时钟
- **32×8 实时预览**：所见即所发（未推送时也照常渲染预览）
- **后台三路发送**：像素 60 fps / 表头 10 Hz / 授时 10 s
- **功耗封顶**：上位机侧先做一次（Σ(R+G+B) 超 12755 整帧等比压暗），固件再做第二次兜底
- **菜单栏常驻**：关掉窗口只是隐藏，后台继续推送；从菜单栏图标可调回窗口或退出

## 运行

```bash
cd host
cargo run            # debug，验证用
cargo run --release  # 长期运行用，渲染更顺
```

首次编译会拉 gpui + sysinfo + mdns-sd 及其依赖（约 1 分钟）。

**⚠️ 别在 Finder 里双击 `target/release/dashboard_host`。**
它是裸的 Unix 可执行文件，macOS 不知道这是图形程序，会用 Terminal.app 当宿主来跑 ——
于是先弹一个终端窗口，主界面再从终端里冒出来。要正常启动请用下面的方式打包：

```bash
./package_macos.sh            # 编译 + 生成 Dashboard.app
./package_macos.sh --no-build # 只打包，不重新编译
```

之后双击 **`Dashboard.app`** 即可，由 WindowServer 直接拉起，不再有终端窗口。
首次打开若被 Gatekeeper 拦下，**右键 → 打开**（自己编译的本地程序都这样）。

> 脚本做的事：组装 `Contents/MacOS` + `Info.plist`（声明 `NSPrincipalClass=NSApplication`、
> `CFBundlePackageType=APPL`），再做一次 ad-hoc 签名让系统记住"用户确认过"。
> 没有引入任何新依赖。

**启动后右上角「选择设备 ▼」里会出现形如这样的项**（发现到第一台会自动选中）：

```
● dash-A292CE · 192.168.5.146:8551 · 256灯5表 · v1.0.0
```

选中 ≠ 推送。流程是：

1. mDNS 发现设备 → **自动选中第一台**（按钮变绿只表示"有目标"）
2. 左列选灯阵数据源、右列选表头数据源
3. 点底部「**开始推送**」→ 按钮变红显示「停止推送」，右上角显示「推送中 → 设备名」

再点一次已选中的设备 = **取消选择**（若正在推送会一并停下）。
点「停止推送」后设备 5 s 自动降级，不需要额外协议。

## 架构

```
host/
├── Cargo.toml          # gpui 0.2.2 + sysinfo 0.32 + mdns-sd 0.20 + rustfft
│                       # （macOS 另加 screencapturekit = 10，用于抓系统音频）
├── build.rs            # 嵌入 Info.plist + 补 Swift 运行时 rpath（详见文件注释）
├── Info.plist          # 供 embed 用，关键在 NSScreenCaptureUsageDescription
├── package_macos.sh    # 打 Dashboard.app（含同一份权限声明）
└── src/
    ├── main.rs         # GPUI 界面 + 后台调度循环 + 设备选择 + 文字/频谱切换
    ├── discovery.rs    # mDNS/DNS-SD 发现：browse _dashboard._udp → 设备表
    ├── protocol.rs     # UDP 三类包构造与发送（type=1/2/3）
    ├── metrics.rs      # sysinfo 采集 6 指标，归一化到 0..65535
    ├── render.rs       # 字符串 / 频谱 → 32×8 行优先 RGB
    ├── font5x7.rs      # 5×7 ASCII 字模表（Adafruit GFX 公共领域字库）
    ├── audio.rs        # ScreenCaptureKit 抓系统音频 → 混单声道 → 环形缓冲
    └── spectrum.rs     # Hann 窗 + FFT 2048 → 线性+对数混合分 32 段 → dB → 平滑 + 峰值白点
```

> 音频采集跑在**独立线程**上（SCStream 不能跨线程移动），回调里把 PCM 混成
> 单声道写进环形缓冲，UI 线程每 16 ms 取最新 2048 个样本做 FFT ——
> 两边不共享 stream，只在缓冲上碰头。

## 音乐频谱（抓系统正在播放的声音）

灯阵数据源切到「**频谱**」即可：灯阵变成 32 段柱状频谱。
表头是**另一路独立开关**——想要 5 路指针跟着音乐走，把「表头数据源」切到「音频频段」，
分别对应 **低频 / 中低频 / 中频 / 中高频 / 高频**。

音频采集是**按需启停**的：灯阵和表头两边都不用音频时才停（录制指示灯熄灭）。
所以「灯阵走文字 + 表头走音频频段」也会亮指示灯，这是正常的；
灯阵切到「无」时若表头仍走音频频段，采集也照旧开着。

### 为什么不需要装虚拟声卡

macOS 出于隐私沙盒，默认不允许任何 App 读到系统正在播放的声音。
常见做法是装 BlackHole 之类的虚拟声卡做回环，但那要装驱动、重启、
在「音频 MIDI 设置」里建多输出设备，还会让键盘音量键失效。

这里改用 **ScreenCaptureKit（macOS 13+）直接抓系统音频**，零安装。
代价是需要一次 TCC 授权 —— 这是纯粹的权限门，**没有任何 entitlement 能代替用户手动点允许**。

### 首次使用：授权一次

1. 切到「频谱」模式（首次会弹系统授权框）
2. 若没弹或点了不允许：
   **系统设置 → 隐私与安全性 → 屏幕与系统音频录制** → 勾选本程序 → **重启程序**
3. 状态灯变绿、显示「正在采集系统音频」即可

> 采集期间菜单栏会有录制指示灯，这是 macOS 的强制提示，无法关闭。
> 切回「文字」模式会停止采集，指示灯随之熄灭。

### 采集自检（不开界面）

```bash
cargo run -- --probe-audio
```

跑 5 秒并打印：权限状态、PCM 格式（f32/i16）、累计样本数、RMS 与峰值。
**频谱没反应时先跑它**，能一次定位是权限、格式还是没声音。

| 打印结果 | 含义 |
|---|---|
| `Failed(... TCC ...)` | 没授权，去系统设置勾选后重启 |
| `Running` 但峰值 ≈ 0 | 权限有了，但系统当前没在放声音 |
| `Silent` | 启动 3 秒后仍无样本，检查是否在播放 |

### 实现要点

| 环节 | 取值 / 做法 | 理由 |
|---|---|---|
| 采样 | 48 kHz 立体声，只注册 `Audio` 回调 | 只抓音频，不收视频帧，零画面开销 |
| 窗函数 | Hann | 不加窗频谱泄漏会让相邻频段互相污染 |
| FFT | 2048 点 | 23.4 Hz 分辨率 / 42.7 ms 时延。1024 点的 46.9 Hz 撑不起低频分频（见下） |
| 分频 | **低频线性 + 高频对数**：40~400 Hz 线性 12 段（30 Hz/段），400 Hz~8 kHz 对数 20 段 | 纯对数的低频段宽只有 ~8 Hz，比 bin 宽还窄 → 最左 4 段被压进同一个 bin，四根柱子读数一模一样 |
| 高频上限 | 8 kHz（8 k 以上不给列） | 音乐在这个区间能量极低，给列也是常年黑着 |
| 倾斜补偿 | **关闭（0 dB/oct）** | 音乐频谱天然按约 −3 dB/oct 衰减，补偿能让右半边亮一点，但会把底噪一起抬上来，观感不实。实测关闭后高频只矮约 1 格，右侧并没有死掉 |
| 幅度 | 每段取 bin 最大值，转 dB（−70…−8 dB） | 取均值会把鼓点抹平 |
| 平滑 | 上升 τ=30 ms、下降 τ=220 ms | 上升快下降慢，柱子才有弹跳感 |
| 峰值白点 | 上升时**贴在柱顶**；柱子开掉后**先停 800 ms**，再以 1.6 满量程/秒缓慢下落，**停在最底一行** | 上升阶段一定看得见白点；下落**慢于**柱子（柱子约 460 ms 到底，白点约 550 ms），白点始终悬在柱子上方慢慢飘落；不归零所以不会闪一下消失 |

### 想再调怎么办

都在 `src/spectrum.rs` 顶部的常量里，改完 `cargo test` 就能看到效果：

| 常量 | 作用 | 调大的后果 |
|---|---|---|
| `F_HI` | 频率上限（默认 8000） | 右侧更高频的列会变暗，超过 10 kHz 基本常年不亮 |
| `LINEAR_BANDS` | 低频线性段占几列（默认 12） | 低频看得更细，但必须保证段宽 > bin 宽（23.4 Hz），否则又会出现「相邻列共用 bin」 |
| `TILT_DB_PER_OCTAVE` | 高频补偿（默认 1.5） | 右半边更亮，但超过 3 dB/oct 会把底噪抬成常亮 |
| `DB_MIN` | 显示下限（默认 −70） | 调到 −80 静音时会冒出底噪柱子 |
| `PEAK_HOLD_SEC` | 白点延迟多久才开始掉（默认 0.8 s） | 白点在柱顶停得更久。柱子自己约 460 ms 就到底，所以 0.8 s 意味着柱子掉完白点还会在空中多悬约 0.34 s |
| `PEAK_FALL_PER_SEC` | 白点下落速度（默认 1.6，**单位是满量程/秒**，1.0 = 每秒掉满屏 8 格） | 必须**慢于柱子平均速度 ≈1.9 满量程/秒**，否则白点会追上柱子被顶住，变成「贴着柱子一起掉」就看不出是峰值了。当前 1.6 离临界很近，调到 2.0 以上就会失去峰值感；调到 0.6 会显得迟迟不落 |
| `TILT_DB_PER_OCTAVE` | 高频补偿（默认 **0 = 关闭**） | 想让右半边亮就设回 1.5；超过 3 会把底噪抬成常亮 |

三个离线核对工具（不用开界面、不用授权）：

```bash
cargo test dump_band_map -- --nocapture              # 打印 32 列的频率/bin/增益映射表
cargo test preview_music_like_signal -- --nocapture  # 用仿音乐信号画 ASCII 柱状图
cargo test dump_peak_trace -- --nocapture            # 静音后柱子与白点各自掉多快的时序表
```

## 服务发现怎么工作的

固件注册 `_dashboard._udp`，上位机 browse 它，**两端都不需要知道 IP**。

| 决策 | 原因 |
|---|---|
| 端口从 **SRV 记录**取，不写死 | 固件将来改端口时上位机不用改 |
| 每次 `ServiceResolved` 都刷新地址 | DHCP 换租后能自动跟上，**别缓存 IP** |
| `ServiceRemoved` 剔除下线设备 | 选中项若下线会自动停推送并提示「选中的设备已离线」，随后改选列表里第一台 |
| 发现后自动选中第一台 | 少一步点击；顺序按名字排序（`Discovery::devices()`），不会跳来跳去 |
| `poll()` 每 16 ms 一次 | mdns-sd 用容量 10 的有界 channel，不排空会堵死 daemon |

**命令行交叉验证**（不依赖上位机）：

```bash
dns-sd -B _dashboard._udp                    # 应列出 dash-A292CE
dns-sd -L dash-A292CE _dashboard._udp local. # 看 SRV 端口 + TXT
ping dash-A292CE.local
```

上位机侧也可以单独验证发现逻辑是否正常（不启动 GUI）：

```bash
cargo test discover_probe -- --ignored --nocapture
```

## 可调参数（都在 `src/main.rs` 顶部）

| 常量 | 默认 | 说明 |
|---|---|---|
| `PIXEL_COLOR` | `(0,220,160)` 青绿 | 灯阵文字颜色（RGB） |
| `BRIGHTNESS` | `60` | 全局亮度（固件侧硬上限 128） |
| `SCROLL_MS_PER_COL` | `80` | 滚动速度（ms/列，越小越快） |

打包相关的常量（`APP_NAME` / `DISPLAY_NAME` / `IDENT`）在 `package_macos.sh` 顶部。

量程（网络/磁盘速率满偏值）在 `src/metrics.rs` 的 `Ranges::default()`：
- 网络 10 MB/s 满偏
- 硬盘 50 MB/s 满偏

## 限制

- **只支持 ASCII**（5×7 点阵字库没有中文）。输入中文会被静默跳过。要支持中文需换矢量字体光栅化（ab_glyph/fontdue + 中文字体子集），代价是依赖变大、渲染变慢。
- **键盘符号不全**：Shift 组合符号（如 `!` `@` `#`）gpui 的 keystroke 给的是基础键，会推成基础字符。字母/数字/空格/Backspace 正常。
- **输入框聚焦**：点击输入框区域获得焦点（边框变蓝），按 Esc/Enter 失焦；失焦后键盘事件不进输入框。
- **下拉框**：自实现的简易版（点击展开内联列表，再点选项选中），不用浮层，布局会短暂推开。稳定可靠优先于美观。

## 与固件对接验证顺序

1. `dns-sd -B _dashboard._udp` 先确认能搜到设备（搜不到先查 AP 隔离，见 [../docs/07](../docs/07-host-integration.md) §0.1）
2. `cargo run` 启动上位机，右上角设备按钮应**已自动选中**第一台（按钮变绿）
3. 点底部「**开始推送**」：灯阵显示滚动字符串（默认 `HELLO`），右上角显示「推送中 → 设备名」
4. 5 个表头应跟随「表头数据源」动：系统指标下 CPU/内存变化最明显；
   切到「音频频段」则跟着音乐走（需要先在系统设置里授权音频录制）
5. 点「**停止推送**」，界面回到「未推送」，5 秒后模块表头转演示扫针、灯阵转彩虹时钟
6. 串口看 `[LIVE] ... bad=0` 确认包格式正确（bad>0 说明包写错了）

## 字模来源

`src/font5x7.rs` 由 Adafruit GFX 库的 `glcdfont.c`（公共领域）转换而来，
每字符 5 字节、每字节一列、bit0=最上行。覆盖 0..255（含扩展 Latin-1 符号）。
